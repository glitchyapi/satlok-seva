How “notify all users” works

There is no push server and no user database — that is deliberate, so no bhagat's data is ever collected.
1. You publish a release here. It writes one signed manifest.json to GitHub Pages.
2. Every installed app reads that universal URL on launch (and on manual check).
3. If the build number is higher, the app raises a system notification on that device: “New update available”.
4. Tapping it opens the update sheet, which downloads only the files whose SHA-256 changed, verifies the signature, swaps them in and reloads.
5. If the release also carries a new APK, the app downloads it, verifies its hash and hands it to the Android installer.

Release signing key

The manifest is signed with RSA-2048 / SHA-256. The matching public key is pinned inside the APK, so even if someone takes over the file host they cannot push code to your users.
No key loaded
Keep the private JWK offline and backed up. If you rotate it, you must ship a new APK with the new public key pinned, otherwise devices will reject your manifests.

Universal source & mirrors

The app reads one universal manifest URL. File mirrors are tried in order if the primary host fails — this is where a OnlyFiles-style direct-link host plugs in.

Danger zone

Rolling back republishes the previous manifest. Devices that already applied a newer patch will roll back on their next check.
